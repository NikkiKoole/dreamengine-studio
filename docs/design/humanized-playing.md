## 1. The problem

A note in our engine is pitch, velocity and length, and every note of an instrument sounds nearly the
same. That is a keyboard. A guitarist never plays the same note twice: where the pick lands, how hard,
a finger pressing a few cents sharp, a strum whose strings land milliseconds apart. A flute note scoops
into pitch, its vibrato arrives late, the breath runs out over a phrase. A tabla stroke is a choice of
which overtones the fingers let ring, and the left hand keeps bending and damping the bass drum after it
strikes. None of that is noise; it follows the body and the phrase.

The question these spikes ask: can a cart (and Playtime) get that, and what does the engine need?

## 2. The shape that keeps coming back

Every spike, and Playtime's choir independently, landed on the same three ideas:

1. **A player model with slow, correlated state**, not fresh dice per note: stroke energy over a phrase,
   a chord grip with one weak finger, an air supply that empties, a wrist position, a singer tiring over
   a song. The per-note values fall out of that state. This is close to an Elektron **p-lock** (a
   per-step parameter value), but the values are generated by the body instead of written per step.
2. **Notation as named articulations.** The name says HOW, the model fills in the micro-values: a
   strum's `D` / `U` / mute / lift, a flute's tongued `t` / soft `d` / slur / breath, a tabla's bols
   (`na` = rim, ring; `te` = closed; `dha` = `na` + `ge`), a sung syllable. Far richer than notes plus
   velocity, and it reads like the instrument's own notation.
3. **Layers you can switch off** (keys 1-5 in every spike), so the ear can tell which part matters.

## 4. Engine findings

### 4.1 Four engines have an always-on vibrato

`INSTR_PIPE`, `INSTR_REED`, `INSTR_BOWED` and `INSTR_BRASS` each carry a built-in "humanized" vibrato
(wandering rate and depth) that starts on the FIRST SAMPLE of every note at the same depth, and a cart
could not turn it off. That is exactly the keyboard tell: real players start a note straight and let
the vibrato bloom.

Done (2026-11-04): **`instrument_vibrato(slot, amount)`**, one call for all four engines. 1 = as the
engine plays it (the default, bit-identical), 0 = off so the cart plays its own with
`note_lfo(LFO_PITCH)`, up to 2 = deeper. Read LIVE per sample, so riding it on a slot fades the vibrato
in on notes already sounding (a solo instrument on its own slot). Measured on a held PIPE A4: pitch
wobble 6.6 cents (std) at 1, 0.4 at 0.

It replaced a first, PIPE-only `MODE_PIPE_STILL` (an `instrument_mode` index, same day, never
committed). One call beats a mode per engine because the mode indices differ per engine (`BOWED`
already uses 0-2), so the same idea would have had four names and four numbers, and a wrong index is
silently ignored.

### 4.2 A booked note can only be shaped at its onset

`schedule_note_at` + `NoteOpts` gives per-note gain, accent, glide and macro OFFSETS at the start.
Nothing after: no bend, no late vibrato, no swell, no damping. Every spike hit this:

- guitar: per-note cents and pick noise had to be faked by setting each string's SLOT
  (`instrument_tune`, `MODE_STRING_CLICK`) ~120 ms before the pluck; works only because each string
  owns a slot
- flute: everything happens during the note, so the cart holds notes live (`note_on`) and rides them
  per frame, giving up booking
- tabla: the bayan's bend and the palm's damping ride the bayan SLOT (`instrument_tune`,
  `instrument_level`, both live); works only because there is one bayan

A live-held note lands 20-40 ms late against booked ones (frame quantization plus the audio block),
too sloppy for fast strokes, which is why booking is not optional for Playtime.

Related engine facts found on the way: slot macros (`instrument_harmonics/timbre/morph`) are read at
note-on only, so they cannot shape a ringing booked note; `instrument_level` and `instrument_tune` ARE
live per slot; `note_aux` reaches `INSTR_VOICE` only.

### 4.3 The ADSR decay is linear in amplitude

Measured: a sine with decay 400 ms, sustain 0 falls in a straight line to zero at 400 ms. Real struck
and plucked things decay exponentially (a straight line in dB). `tablalab` maps a measured t60 to
`0.37 * t60` of linear decay, which matches the first 20-30 dB, but the tails sit 10-15 dB hot at 0.3 s.

## 5. The tabla, measured

Recordings (single strokes, measurement only, never shipped): Freesound CC0 pack "tabla bols" by
mmiron (pack 8162, 12 strokes) and the CC BY 4.0 pack by ajaysm (pack 10737, 13 strokes), kept in the
gitignored `build/refs/` with their provenance. Analysis from 128 kbps previews, so rough above ~10 kHz.

- **Tuning:** the overtones sit on a near-harmonic series (Raman's syahi effect), but the LOWEST mode
  sits ~1.1x above where the series puts it: mmiron 314 Hz over a 279 Hz series (558, 837, 1116...),
  ajaysm 322 over 295. Seen on both drums, so it is the instrument, not one drum's quirk. Our
  membrane assumes a clean 1:2:3:4.
- **A stroke is a choice of overtones**, each with its own decay:

  | stroke | what rings | decay |
  |---|---|---|
  | tun | the fundamental alone | t60 ~2.2-2.4 s |
  | na | 3rd loudest, 2nd under it, fundamental damped (-30 dB) | 3rd t60 0.4 s, 2nd 1.3 s |
  | na (open) | fundamental + 2, 3, 4 | the 2nd OUTLASTS the fundamental (2.4 s vs 1.3 s), 3 and 4 ~0.4 s |
  | tin / tas | the 2nd overtone | t60 ~1.6-2.6 s |
  | te / re / ke | a low inharmonic cluster (60-370 Hz), no ring | 40-280 ms in total |

- **A bright flash at the strike:** the upper overtones start nearly as loud as the main one and are gone
  within ~0.1 s.
- **The bayan's boom is a pitch FALL:** it HOLDS ~117 Hz for ~90 ms, then drops ~5 semitones to ~89 Hz
  by ~170 ms. Our membrane's chirp is smaller and quicker (~90 ms), and sat too low (84 to 75 Hz).

`INSTR_MEMBRANE` cannot make these strokes: one strike-position knob tilts all six modes together, and
the upper modes always die faster than the lower. `tablalab` matches the onsets within 1-5 dB per
overtone for tun, na, na-open and tin.

## 6. The needs list (gathering; nothing here is decided)

What a booked note would have to carry, from every instrument so far. Numbers marked *(guess)* are what
a spike's model produces, not yet judged by ear.

**The framing:** in every spike and in the choir, the player model (hand, breath, phrase, tiring,
personality) lives entirely in the CALLER and turns into plain per-note values. The engine only needs to
CARRY curves and per-note choices, not model a player.

### 6.1 Shared

- **A pitch curve, as breakpoints**, not just a decay: an onset scoop (cents + settle time, ease-out),
  a vibrato with depth, rate and a fade-in delay, and a slope over the note (a singer's breath sag, the
  bayan's hold-then-drop). One breakpoint curve type serves the voice and the drums.
- **A gain curve:** swell on long notes (messa di voce), fade on phrase-final notes.
- **A timbre / macro value per note**, static at onset at least; a curve over the note for the tabla's
  palm pressure (tone changing while it rings).
- **A curve time origin** (from the voice, §6.3 item 8): curves count from where the pitched body begins
  (a sung vowel after its consonant; a drum's ring after the strike click), not from note-on.
- **Curves end with the sound** (§6.3 item 9): no sustain implied; a short one-shot just stops.
- **A sample region (or take) chosen per note, latched at note-on** (§6.3 item 10): today
  `instrument_sample_region` is read live from the slot, so two overlapping notes on one slot cannot
  play different chops. Matters for any recorded take, the drums included if a stroke ever becomes one.

### 6.2 Drums and strikes (tabla)

1. **Touch per stroke:** each overtone's level and decay set per stroke (§5 table). The core of the
   character; likely a `MODE_*` / data recipe on `INSTR_MEMBRANE` rather than a note curve.
2. **The onset flash** of upper overtones in the first ~0.1 s.
3. **Exponential decay** (§4.3).
4. **The bayan pitch curve:** hold, then fall (a breakpoint, see §6.1).
5. **Tone while ringing:** palm pressure dulls and shortens the bayan as it sounds.
6. Open vs closed strokes currently need two slots per drum plus `instrument_choke`, because release
   length is per slot.

### 6.3 Voice (from playtime-97's choir spike, verbatim in substance; all numbers *(guess)*, unjudged)

Sung mipomi syllables: one recorded take per syllable, 0.2-0.7 s, three speakers.

1. **Base tuning.** Each take has a measured pitch (pYIN median of the vowel's steady middle); the note
   plays at the offset from it, -14..+14 semitones in practice. Today a resample (pitch and length
   together, chipmunk past ~4 st). Wanted: length kept, i.e. `INSTR_SING`.
2. **Onset scoop.** 8-120 cents under, rising to the note in ~80 ms (linear now; ease-out truer). Grows
   with the leap up: min(120, 10 c per semitone) x 0.6-1.0, +30 c when tired; ~8 c on steps and repeats.
3. **Vibrato.** Depth 10-35 c (25 x (0.4 + 0.6 x breath), x1.3 on a phrase's last note), rate 4.4-7.6 Hz
   (slower when tired, faster and thinner short of breath). Starts 120 ms after the vowel, fades in over
   150 ms, only on notes longer than 0.35 s.
4. **Offset over the note**, -43..+8 c (breath sag -25 x (1-breath)^2, tired -18, push to the phrase top
   +8, slow drift +-5). Static per note in the spike, but a real singer SAGS during the note: a slope,
   so breakpoints (same need as the bayan).
5. **Gain** per note -11..+5.5 dB (static now); wanted within the note: fade on phrase-final notes, swell
   on long ones.
6. **Timbre / size** per note, static at onset (`INSTR_SING` timbre = size); a small wobble optional.
7. **Timing** (booking only, no engine part): -30..+90 ms (lean, rush to the phrase top, ritard into the
   last note, +35 ms after a snatched breath, late landing on leaps, dragging when tired).
8. **A curve time origin.** A take starts with its consonant; the vowel begins 0-0.45 s in (measured per
   take). The booking moves earlier by that lead so the vowel lands on the beat, but scoop, vibrato onset
   and sag must count from the VOWEL. So: a per-note offset for curve time zero (or curves in absolute ms
   from note-on and the caller adds the lead).
9. **One-shot syllables are often shorter than the note.** Curves must not assume the sound lasts the
   note; the vibrato / gain curve ends with the take, no sustain implied.

10. **A take per note, from a bank.** A choir needs many takes at once: 39-45 syllables x 3 speakers
    = ~120 takes (0.2-0.7 s each), a song uses ~14 per speaker. The engine has 8 sample slots (8 s
    each), and `instrument_sample_region` is read LIVE from the instrument slot ("a dragged chop moves
    sounding voices", sound.h ~5722), so packing syllables into one take and chopping per note breaks
    as soon as two notes on the slot overlap. Wanted: the region (or the take) chosen PER NOTE and
    latched at note-on (NoteOpts start/end, or a take index into a bank), or many more, smaller sample
    slots. Without it sung syllables cannot move to the synth however good the curves are.
11. **Overlap on one singer.** The booking starts early by the consonant lead (up to 0.45 s), so the
    next syllable starts while the last one's tail still sounds. A singer's slot must not be mono or
    choke itself: at least 2 voices per slot, or the tails are cut, audible as clipped vowels.

**Update (2026-11-04, playtime-97, the WORLD vocoder; Nikki: "very promising", "I really like the
world ones"):** item 1 is now met WITHOUT the engine by baking offline: `claudetools/voice-bake.py`
(Playtime) re-tunes every sung syllable with WORLD (pitch curve moved, spectral envelope and length
kept) to a pitch every 3 semitones; the game plays the nearest and resamples the rest (at most 1
semitone). As in tune as resampling (42/42 notes within half a semitone), lengths x1.00-1.02 instead of
x0.63-1.19, no chipmunk; 1023 files / 7.7 MB for 31 syllables x 3 speakers. So for tuning the voice no
longer needs `INSTR_SING`; what still needs the engine (or more baking) is a per-note SIZE and anything
continuous. Item 10 grows: ~1000 short takes instead of ~120. A possible need, not a request:
**morphing between takes** (one syllable turning into another, one speaker into another, a fixed 50%
blend that lands between two voices; a crossfade sounds like two voices), offline only today; live it
would mean two takes per note with a blend curve, i.e. analysis-domain (envelope + f0) playback, not
PCM. Details: Playtime `docs/CHOIR.md` "WORLD".

Not needed by the voice: overtone selection, the onset flash, exponential decay (drum needs; the voice's
timbre comes from the take).

### 6.4 Guitar, flute, reed, bass

- guitar: per-note **cents** and **pick noise** (today slot state set early, §4.2); a per-string mono
  voice (have it: `instrument_mono`)
- flute: everything in §6.1 (scoop, late vibrato, swell), plus the built-in vibrato switched off (§4.1)
- reed: §6.1 plus a **macro curve over the note** (the breath/growl macro rising after the attack) and a
  **fall** (pitch dropping ~3 semitones over the last third while fading): both post-onset, so a curve
- bass: a **slide into the note** (a pitch curve from 1-2 semitones under, rising in 60-120 ms; a
  waveguide string cannot START above and bend down, so the curve must begin low); per-note **gate**
  (have it); a ghost (dead) note needs a second, hard-damped slot plus `instrument_choke`, the same
  open/closed two-slot pattern as the tabla (§6.2 item 6), so **a per-note damping amount** would
  remove a slot from both

### 6.5 Cello, piano, drum kit (the §7.1 spikes; built by three parallel agents 2026-11-04)

All measured, none judged by ear yet. Engine facts below were checked against `runtime/sound.h`.

- **An event INSIDE a held note** (cello bow change; the hi-hat foot closing on a ringing hat).
  Starting a new voice is a RE-ATTACK, not a bow change (the bowed string needs ~0.4 s to build back
  up, partials ~4-5 cents off at the join). `note_retrig` does nothing on a bowed note: it re-arms
  onsets for PIPE / REED / BRASS / ORGAN only (`sound_retrig_voice`). What worked: riding the held
  note (a 4-8 dB dip for 30-90 ms, a timbre blip) plus a noise tick on a second slot. The physical
  answer is a **signed bow-velocity curve** (the string lets go and re-catches); today bow speed has a
  floor (`bowSpeed = 0.30 + mor*0.60`) and cannot reach zero or reverse.
- **A curve SHARED by every sounding note** (sustain pedal, hi-hat pedal; the accordion bellows is
  the same kind). The piano's morph "pedal" is latched into the string's loop loss at note-on
  (`pn_dampg = pn_damps = v->mor`) and never re-read: a held note with `note_morph` changed mid-note
  renders BYTE-IDENTICAL. So `pianohand` computes the dampers itself and books each note's gate to
  end at key-up or the next pedal lift. A booked note cannot follow a curve that is decided later, and
  a half pedal cannot change a ringing note's decay RATE. Need: a per-slot (or group) damper/pedal
  amount that every sounding note follows live, booked ones included, with a per-note "key held" flag
  the pedal curve cannot damp; timed on the audio clock (riding per frame lands ~17 ms late and steps).
- **How a note ENDS**: release time is copied into the voice at note-on, so `pianohand` uses 5
  identical slots for 5 release lengths. The release is a LINEAR ramp (-6 dB at half, then a plunge;
  a felt damper is the reverse: a quick drop then a short tail) and ends in exact digital silence.
  Need: **a per-note release time + shape** in NoteOpts; an **end event** (damper / key-off noise).
- **A technique per note = a BUNDLE of voices fired together** (rimshot = head + wires + rim crack;
  flam / drag / buzz = 2-9 strokes), each with its own gate, strike spot and filter. Measured distinct
  (cross-stick centroid 576 Hz vs a centre hit ~3.5 kHz). Today: several `schedule_note_at` calls.
- **A per-note filter cutoff** (drums: today only via `ACC_CUTOFF`, one amount per slot) and a
  **per-note decay / damping amount** (drums: `MODE_METAL_DECAY` is per slot; the THIRD instrument
  asking, after bass and tabla).
- **Sound-setting curves over a note**, confirmed on bowed: morph (bow speed) is live (+6.8 dB),
  timbre (pressure) is live but weak (centroid 1004 to 1142 Hz, the scratch nearly inaudible),
  harmonics (bow position) is note-on only. Need also: **bow position per note**, latched at note-on.
- **Engine sound gaps found on the way** (not NoteOpts): bowed pressure needs more spectral range;
  the piano's treble decays far too fast (C6 down 40 dB in ~0.4 s whatever the pedal setting).
- Slides inside a legato pair are bookable today (mono slot + `glide_ms`), but a bowed string can only
  go ~7 semitones under its start (the 2.5x string buffer, capped).
- **The kit voiced against CC0 recordings** (dreamengine-f4, `64ef3ec3`; references in
  `build/refs/drums-cc0/`, lennartgreen's "Vintage Hip Hop" kit + a cross-stick, with the cymbals):
  - **Per-note FILTER, now with evidence:** the ride bow wants a LOWPASS ~1.5 kHz (its wash is
    0.4-2 kHz) and the bell a BAND ~5 kHz, so the bell had to move to its own slot (`S_BELL`): one
    technique bundle on one cymbal, opposite filters.
  - **`INSTR_MEMBRANE`'s second mode is too weak for kit drums:** real kick, rack and floor tom each
    carry a mode ~2.1x up at only 1-5 dB down (kick 118 Hz, rack 269, floor 183); the membrane leaves it
    17-20 dB down at any strike position, so it is booked as a second voice (+13 semitones). An
    engine-side mode-balance control would remove that (engine sound gap, not NoteOpts).
  - **`INSTR_METAL`'s built-in noise sits at 15-20 kHz, so cymbals need a LOWPASS;** the bogie recipes
    HIGH-pass, which is what made the first cymbals hiss (the crash was 3-20 kHz, spectral flatness
    0.82). The `metal/*` rows in `guides/instrument-recipes.md` may deserve a note.
  - **The ride (Nikki heard a "train locomotive"):** each ride stroke was its own voice ringing 1.3 s, so
    eighth notes stacked into a low pulsing drone. Kit rule: **one physical cymbal = one voice** (mono
    slot). And no single engine gave a ride both its body and its high shimmer without filling the mids,
    so a stroke is TWO mono voices (METAL shimmer + MODAL body ~590 Hz), aimed at a CC0 ride Nikki picked
    by ear (refs `build/refs/drums-cc0/ref_ride_*`; dreamengine-f4, drumhand commits ending "the ride
    gets its stick hit").

### 6.6 A synth: humanizing the MACHINE (2026-11-04, `synthhand`)

A synthesized sound has no body, but it has a player's HANDS and a MACHINE that is imperfect, and the
second half is a different kind of need: not per note, not chosen by the player, a property of the
INSTRUMENT.

- **The player's knobs are curves shared by the instrument**: a hand riding the cutoff (slow, uneven,
  a little springy overshoot) moved the brightness between ~390 and ~1380 Hz through a phrase, the
  digital version sat flat at ~700 Hz. The same row as the piano pedal (§6.5). Plus mod-wheel vibrato
  arriving late, bends into notes, glide on some notes: all covered by §6.1's curves.
- **The machine: VOICE CARDS.** Real analog polysynths give each voice its own small offsets (tuning
  a few cents, cutoff ~10%, envelope speed ~15%, level) and hand notes out in rotation, so the same
  note twice sounds twice; oscillators DRIFT (more while cold); a big chord SAGS the supply. Our
  engine plays every voice identically and exactly in tune. `synthhand` fakes it cart-side with eight
  slots of one patch, each offset, round-robin, ridden every frame. Proposed if it proves to carry
  the beauty: **`instrument_analog(slot, amount)`**, an instrument property (like `instrument_vibrato`):
  per-voice fixed offsets + slow drift (+ maybe sag), one slot instead of eight. Not a NoteOpts field.
- **The layer A/B (Nikki, 2026-11-04): the voice CARDS carry it** ("I like what cards is doing"); drift
  is hard to hear on its own "but it feels nicer on too" (below the threshold of noticing, felt as
  aliveness). So the machine half is worth an engine feature: `instrument_analog(slot, amount)` with
  per-voice offsets as the main ingredient and a small drift folded in, not a separate call.
- **Built: `instrument_analog`** (`84ebf1ba`, 2026-11-04): 8 voice cards round-robin at note-on, offsets
  hashed from (slot, card) and scaled by amount (tune +-7 cents, cutoff +-10%, envelope speed +-15%,
  level +-0.7 dB at 1), drift +-3 cents refreshed every 64 samples. 0 = byte-identical. The same note 8
  times at 1: pitch -5..+4 cents, level +-0.6 dB, centroid 584-649 Hz.

### 6.7 Formants: a mouth on any sound? (2026-11-04, `mouthhand`): answered

The question: can a moving formant (a vowel filter) humanize ANY sound, the way the voice cards do?

- **Measured:** riding today's `instrument_formant` works. Smoothed in the cart and re-sent only when
  it moves, there is no zipper (worst click scores identical moving vs frozen); the lead's main
  resonance wanders ~600-2450 Hz moving vs ~620-1030 Hz frozen; open vowels add gain (the first render
  clipped; trim the slot levels). The engine jumps to a new vowel (no slew), and the vowel is not an
  `fx_mod` target.
- **Verdict (Nikki):** better, not wow. **As a general humanizer a moving formant is a small ingredient**,
  like drift: worth doing, not a headline.
- **Where the wow lives, from real players** (sources in the guide §5): a talk box says WORDS (the
  consonants make the illusion of speech: lips closing, stops, fast glides), all of the sound goes
  through the mouth, the source is a bright open sawtooth, the shapes are exaggerated and the pitch
  bends into words (Roger Troutman); and the funk bass "quack" is a touch-wah, a resonant filter swept
  by how HARD each note is hit (Bootsy's Mu-Tron III). Brass wah-wah is a plunger opened and closed in
  rhythm (Bubber Miley, Cootie Williams, Tricky Sam Nanton's "ya-ya").
- **Those are two specific effects, and both mostly exist already:** talking = the vocoder with a
  voice-engine modulator speaking consonants (`vocode`; `INSTR_VOICE` + `voice_consonant`/`voice_coda`,
  `say`, `vox`), the touch-wah = `instrument_wah` (in `clavinet`, `epiano`, `afrobeat`, `pedalboard`).
  A talking synth is a cart/feature goal of its own (the parked "talkbox / Dalek" toy in

## 8. Proposal: the NoteOpts layout (DRAFT, 2026-11-04, not built)

> Written against the needs in §6 (every spike + Playtime's choir). **Not built: building is on hold**
> until Nikki says go; this is the shape to agree on first, then check with playtime-97 against
> singing before any `sound.h` edit.

### 8.1 Rules the layout follows

1. **The player model stays in the caller.** The engine carries decisions (values, curves), never a
   model of a player (playtime-97's framing, §6).
2. **Zero means "as the slot is".** Every new field defaults to 0 = today's behaviour, so existing calls
   (designated initialisers, `NULL`) stay byte-identical. New fields are APPENDED to `NoteOpts`.
3. **Fixed size, no allocation, realtime-safe** (AUv3, the audio thread).
4. **Units as `studio.h` already speaks them:** cents for pitch, dB for gain curves, octaves for cutoff,
   0..1 offsets for the three macros, ms for time.
5. **It has to fit the plumbing.** Today `schedule_note_at` BIT-PACKS `NoteOpts` into three ints of a
   `SoundReq` (`.e0/.e1/.e2`: glide, accent + gain, the three macros at 10 bits each). Curves cannot fit
   there, and growing `SoundReq` is costly because the cart contexts log requests (8 x 1024 entries). So
   curves travel as REFERENCES to shapes defined once (8.3), and anything per-note that does not pack
   goes through a fixed engine-side payload pool indexed from the request (8.7).

### 8.2 Per-note scalars (appended to NoteOpts)

```c
typedef struct {
    // today (unchanged)
    int   glide_ms; float accent, harmonics, timbre, morph, gain;
    // new: all 0 = as the slot is
    float cents;          // fixed pitch offset (guitar finger pressure, voice tuning)       §6.4, §6.3
    float cutoff_oct;     // filter offset for THIS note, octaves (ride bow vs bell)          §6.5
    float damp;           // 0 = the slot's ring .. 1 = stopped at once (closed stroke, ghost) §6.2/6.4/6.5
    int   release_ms;     // 0 = the slot's release; else this note's                        §6.5
    int   origin_ms;      // where curve time 0 is, after note-on (the vowel after the consonant) §6.3 #8
    float region_start, region_end;   // INSTR_SAMPLE/SING: this note's chop, LATCHED at note-on (0,0 = slot's) §6.3 #10
    NoteVib   vib;        // 8.4
    NoteShape shape[3];   // 8.3: up to three curves on this note
} NoteOpts;
```

`damp` is engine-specific in meaning but one idea: how much of the instrument's natural ring this note
keeps (a membrane's mode decay, a string's loop loss, a sample's release). It removes the second slot
the tabla, the bass ghosts and the drums all needed (§6.2 item 6).

### 8.3 Curves: a shape library, referenced and scaled per note

A player re-uses the same gestures (a scoop, a fall, a swell, a bayan drop, a growl coming in) at
different sizes. So shapes are defined ONCE (set-and-hold, like an instrument) and each note references
up to three, scaled:

```c
void shape_define(int id, int n, const float *t_ms, const float *v, int interp);
//   up to 6 breakpoints; interp SHAPE_LINEAR / SHAPE_EASE / SHAPE_EXP; the last value HOLDS
typedef struct {
    unsigned char id;      // 0 = none; 1..63 = a defined shape
    unsigned char target;  // SHP_PITCH (cents) / SHP_GAIN (dB) / SHP_HARM / SHP_TIMB / SHP_MORPH (macro offset)
                           // / SHP_CUTOFF (octaves) / SHP_VOWEL (formant, later)
    float scale;           // multiplies the shape's values (0 = 1.0: as defined)
    float stretch;         // multiplies its times (0 = 1.0): a longer note, a slower swell
} NoteShape;
```

Per-note uniqueness comes from the caller's player model choosing `scale` / `stretch` (and which
shape); the engine just plays it, sampled every 32 samples, from `origin_ms`. A curve ENDS WITH THE SOUND
(no sustain implied, §6.3 #9). This covers: the flute / sax / voice scoop, a fall, a breath sag, the
bayan's hold-then-drop, messa di voce, a phrase-end fade, the sax growl, bow pressure and speed, the
palm dulling the bayan, a per-note "wah" (once SHP_VOWEL exists).

### 8.4 Vibrato as fields, not a shape

It is on almost every wind, bowed and sung long note, and it is a generator, not a line:

```c
typedef struct { float cents, rate_hz; int delay_ms, fade_ms; float wander; } NoteVib;
// cents 0 = none; wander 0..1 = how much rate and depth drift (the engines' built-in vibrato already does this)
```

Pairs with `instrument_vibrato(slot, 0)` (shipped): the slot's built-in vibrato off, the note's own on.

### 8.5 Curves shared by every sounding note: lanes

The pedal, the hi-hat pedal, a synth's knobs, the bellows (§6.5, §6.6). Booked on the audio clock like
notes, ramped sample-accurately, followed by held AND booked notes on the slot (or group):

```c
void lane_at(double t, int slot, int lane, float value, int ramp_ms);
// LANE_DAMPER  0 up .. 1 down: a note whose KEY is up (its gate ended) keeps ringing while the damper is
//              up, at a decay scaled by (1 - damper); a note whose key is down ignores it (the pedal)
// LANE_CUTOFF  octaves offset on every voice of the slot (the hand on the knob)
// LANE_LEVEL   dB (swell pedal, bellows)
// LANE_VIB     vibrato depth scale (the mod wheel)
// LANE_VOWEL   the slot's formant vowel, slewed (a talk box; fixes the formant's jump, §6.7)
```

The hi-hat pedal is `LANE_DAMPER` on the hat slot; the piano pedal the same on the piano. It replaces
the per-frame `instrument_level` / `instrument_tune` riding three spikes used, which steps at frame rate
and lands ~17 ms late (§6.5).

### 8.6 Events inside a note

The cello bow change and the foot closing on a ringing hat (§6.5): a booked note returns an id, and
events address it:

```c
int  schedule_note_at(...);                 // now RETURNS a booking id (> 0), still usable as void
void note_event_at(int booking, double t, int event, float amount);
// NEV_REARTIC  re-articulate without restarting the pitch: re-arm the engine's onset (the bow catch,
//              the chiff) and dip the excitation by `amount` (BOWED: reverse the bow, §6.5)
// NEV_DAMP     set damp from t on (the foot closing, a hand muting)
// NEV_RELEASE  end the note at t (key-up decided later than booking)
```

Engine side this needs `sound_retrig_voice` to cover BOWED and a signed bow velocity (§6.5).

### 8.7 Plumbing (how it travels)

- `NoteOpts` stays a caller-side struct. `schedule_note_at` keeps packing the old six fields into the
  request as today (so nothing old changes) and, only when a new field is non-zero, writes the rest into
  a fixed pool of payload records (e.g. 128 per engine instance) through the same SPSC direction the
  request queue uses, passing the record index in the request. The record is freed when the note fires
  and its values are copied into the voice.
- Shapes live in a per-instance table (64 x 6 points), defined with `shape_define` (a config request,
  logged like `instrument()`, so `de_switch_cart` and session state restore them).
- Lanes are requests booked on the audio clock (like `schedule_at`) holding the current value + a ramp
  per (slot, lane).
- Deterministic and per-instance like the rest (sound_ctx.h, `ctx-gen --verify`).

### 8.8 Coverage: every need, and where it lands

| need (§6) | field |
|---|---|
| pitch curve: scoop, fall, sag, bayan drop, slide | `shape[]` with SHP_PITCH |
| vibrato with a delay and fade-in | `vib` |
| loudness curve: swell, fade, bow-change dip | `shape[]` SHP_GAIN; the dip also `note_event_at` NEV_REARTIC |
| macro curves: growl, bow pressure/speed, palm | `shape[]` SHP_HARM / TIMB / MORPH |
| cents per note | `cents` |
| release time per note; release SHAPE | `release_ms`; the shape: an instrument property (`instrument_release_shape`, 8.9) |
| damping per note | `damp` |
| filter per note | `cutoff_oct` (+ SHP_CUTOFF for a moving one) |
| curve origin; curves end with the sound | `origin_ms`; the rule in 8.3 |
| sample chop / take per note | `region_start/end` (a take index into a bank: later, with Playtime) |
| shared curves: pedal, hi-hat pedal, knobs, bellows | `lane_at` |
| events inside a note: bow change, foot closing | `note_event_at` |
| per-note vowel ("wah") | SHP_VOWEL, needs a per-voice formant (engine voicing work first) |

### 8.9 What stays OUT

- **The player model** and **technique bundles** (a rimshot = three voices): the caller's job; a bundle
  is three `schedule_note_at` calls, maybe a cart-land helper header later, not the engine.
- **Instrument properties**, not per note: `instrument_vibrato`, `instrument_analog`, `MODE_BOW_PLUCK`
  (shipped), and `instrument_release_shape` (linear / exponential / felt damper: the linear release is an
  engine gap, §6.5).
- **Engine voicing gaps** (§6.5-6.7: membrane mode control, exponential decays, bowed pressure range,
  piano treble, per-voice formant): separate work, each measured against recordings.
- **Morphing between sampled takes** (Playtime's WORLD idea, §6.3): far off, analysis-domain playback.
